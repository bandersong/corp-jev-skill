# Playbook — panel, upward verification, modes, delivery, owner machinery

Universal (not class-specific), needed at dispatch time. `SKILL.md` carries the headline of each rule; this file carries
the full form. Load it when you build the panel phase or the delivery step.

Contents: §PANEL · §ORCHESTRATOR · §MODE · §DELIVERY · §OWNER

## §PANEL — mechanics
- 2–3 **fresh** critics, artifacts or frames only — never the VM or the build chain, never the builder's rationale.
  Structured verdicts: per-claim evidence, regressions against the prior round, `could_not_check[]`, and an evidence
  score for the harness itself. Wide-work alternative: a per-lane paired skeptic on the same slice (pattern 5).
- Seats are **per class** (the class file names them) plus ALWAYS a **purpose seat**: does the artifact do its job —
  the message for marketing, audience and persuasion for a letter, decision-usefulness for a report. It caught what three
  opus critics and a full integrator pass had certified. Critics run on opus at `xhigh` (`model.md`).
- **Truthfulness is bidirectional:** burying the core promise is a P0 exactly like overclaiming — for a graded agent,
  "be more cautious" is always the safe move. **The owner's stated direction is the spec**; deviating from it is a decision to
  surface and defend.
- **Every seat decides, then seconds.** A seat calls each failure it lists blocking or not — its own judgment — and its
  READY / NEEDS_EDITS / NOT_READY is the worst of those calls (any blocking → NOT_READY; failures, none blocking →
  NEEDS_EDITS; none → READY). Its one `jev second` carries one `kind: blocker` row per failure (`jev.md` §7); Jev's
  answers route escalation and never change the verdict. The holistic pick (`panel_verdict`, unmeasured) is display
  only. Panel verdicts are floors: never lowered by Jev, never skipped by the ladder. The **ladder**, not the seat,
  decides discretionary verify spend (an N-vote refute panel, a second skeptic, a re-audit): only an item seconded
  agree-and-clear on a measured question stands on its receipt; everything else — every disagreement included — goes to
  a verifier. It never moves the panel floor, a mandatory seat or the final gate.
- **2 asserting vs 1 falsifying is UNRESOLVED, not a defect** — reconcile before it becomes a brief; that arithmetic
  once created a phantom, burned a builder and forced a revert. Hand every seat the **enumerated closure contract** (the
  numbered texts, numbers and tables that must now be true) and the **known-held exclusion list** (in-flight work,
  owner-queue items), and ask it to report every failure against that contract — including the ones it is unsure of,
  each with a severity and a confidence (high / medium / low) — and nothing else: no style preferences, no praise, no
  padding; an empty list is a valid answer. **No mode cuts Jev; only cheap mode, named in the state file, skips the
  panel** (it was once skipped in 5 of 6 loop passes). Condense before synthesis: lanes drop evidence files and pass
  paths.

## §ORCHESTRATOR — verification pointed upward
Every instrument the old skill had pointed downward, and four of the orchestrator's own beliefs were fiction. These
seats are cheap and they are the only ones aimed at the CEO, so they are not what gets cut for budget.
- **Ledger red-team** (1 opus, `xhigh`): its whole area is your last round-log paragraph, checked against primary sources
  and run BEFORE the next wave reads it — it once found 5 errors, including a phantom defect already in flight in a live
  builder brief. **Corrections write-barrier:** they land in the state file before the next wave or panel reads it, and
  the next brief declares them BINDING.
- **Pre-wave claim audit** (sonnet, `high`; pattern 22) before spending builders: score last round's claims LANDED /
  NOT_LANDED / PARTIAL / UNMEASURABLE from artifacts only, and feed the live numbers into the new briefs. Round 1 has
  nothing to claim-audit; from round 2 it is one cheap call, never cut.
- **Independent recount** (sonnet, `high`; pattern 20) at the end of a round: re-derive every tally from raw artifacts in
  code, trust no operator arithmetic, and flag any dispatched item that appears in no results file (that found an 84-doc
  gap).

## §MODE — state the shape and the cost before spending it
The owner's words pick it. `fan out` means a wider wave on the right tiers — never a thinner adversarial layer — in any mode.
- **vibe** ("just vibe it"): one recon lane, N review lanes each with a paired same-tier skeptic, synthesis; no builders.
  Same §JEV ladder and the same per-question bars as every mode; vibe's discretionary set is each lane's paired skeptic,
  skipped on agree-and-clear items (blocker/high always escalate). Its savings come from having no builders, not from Jev.
- **full** (default): the spine, one round.
- **hard** ("hard mode", "token max", "adversarial"): full, plus the class file's extra adversary seats, plus a second
  verification round on the fix. Jev still orders and seconds every one of those seats; it never uses agreement to
  shorten or skip one.
- **deadline** (a named hour): **find the clock and state it before fanning out.** Ship a shippable floor early so the
  campaign is fail-safe; declare the ship gate in advance with a **named fallback artifact** ("at 15:12 I ship whichever
  is better: the fixed brief, or the draft plus my pass"); every later phase is upside. Each brief's TIME slot carries
  `elapsed <n> min / budget <m> min`, with a hard timeout kept separately. **Never cut the adversarial layer to save
  time — cut recon breadth instead.**
- **cheap:** when a scheduled human review IS the next verification pass, the panel is waste — the one mode that skips
  it. Name what still runs (mechanical gates, claim truth, every Jev call and floor) and record in the state file that
  the cheap lane was used. No mode cuts Jev.
- **refresh** (`/corp refresh`): the freshness pass over `sources.json` — `refresh.md`.
- **Round ceiling (CEO decision E14):** declare it at intake, in the state file — full 3 rounds, hard 5, deadline = the
  clock. Stop when a round yields no P0. The ceiling reached with a P0 still open ends the campaign too: STAGED (the P0
  and its fix in the owner queue) or PARKED — never an unbounded repeat. (A domain-specific sibling skill may be stricter: stop
  on no P0 and no P1.)
- In every mode, say the agent count, the tier mix and the token estimate out loud before dispatching. Price it from
  this campaign's measured per-agent spend by tier (`model.md` §Pricing); the old ~134k-per-agent anchor came from an
  all-opus Opus 4.x run and is historical. If that is not what the owner meant by cheap, cut N and tier down, and say so in one
  line. `budget.spent()` is the live counter; put the number in the ledger, not a placeholder.
- An **owner-skipped department** is a named deviation plus a compensating sweep by you: in one campaign, the round
  whose verify was cut is the round an integrator invented a citation into three artifacts. When the owner asks for more machinery than the task
  needs, say so in one line and do it directly.

## §DELIVERY — the last mile
After repeated requests just to locate the output, the rule is: **the exit is not the report, it is the pack the
humans execute.**
- One named folder, one obvious file, handed over as an absolute path (an artifact page only if the owner asks for a shareable
  one). **Deliverable / scaffolding split:** the delivery location holds ONLY what gets delivered — previews, notes,
  receipts and the state file go in one clearly named subfolder — and list the folder before and after when humans share
  it. A packet ships `SEND TO <recipient> (final)/` beside `OFFICE MATERIALS (not for submission)/`, so a mis-send is hard.
- **Gated-marker census** (the delivery gate; distinct from the kit's `assertSlots()`, which guards briefs).
  `scripts/census` over every finished file (CEO decisions E3, E4, F4): every XML part of a .docx, .xlsx or .pptx from
  raw XML — body, tables, text boxes, headers, footers, footnotes, endnotes, comments, the text of charts, drawings,
  SmartArt and WordArt, embedded packages part by part, Strict-format OOXML too — plus PDF and .md/.txt text (a main
  document part that yields no text, or an embedded OLE object, is UNCHECKED, never CLEAN; a bracketed URL, `mailto:` or
  DOI is a citation), counting `[OWNER VERIFY:`, `[OWNER DECISION NEEDED:`, `[… TO COMPLETE]`, `TBD`, the catch-all
  `\[[A-Z][^\]]{2,80}\]` (a legitimate "[Emphasis added]" counts too: reword it) and any leftover `[src:` / `[calc:`
  pointer (the strip before it is a named, counted step), per file and part; exit 1 on any, or on a page it cannot read.
  Unfilled `<slots>` are not among its classes: grep for them as well. `pandoc -t plain` misses headers and footers —
  never the census. **For anything a third party receives — a payer, a plan, an agency, a customer — the census is zero
  or it is not a deliverable:** drop the gated item and record it, or do not emit the artifact. OWNER_GATED is a valid
  report status and an invalid shipped artifact (an enclosure once went out with 7 red fields). The zero rule has no
  exception for recipients. The ONE artifact that keeps markers is a draft built FOR a named human to complete and sign —
  there the markers ARE the anti-fabrication device, and deleting them invites invention — so they stay, get counted, get
  enumerated into the owner queue, the handover says "draft for signature", and it never sits in the send folder.
  Handing it over on a share is an E0 row with the verb `handover`: its census runs `--for-signature` (markers listed and
  allowed, pointers never) and `share-check.sh --record` writes the handover manifest. **When it comes back signed or
  completed, it is adopted, then three checks run before the owner sends it — mandatory, never a recommendation (CEO
  decisions E9, F3):** `share-check.sh --adopt-human <the signed file>` records the signer's copy's md5 as the folder's new base (who and
  when from its `lastModifiedBy` and mtime; the RAIL NOTE line it prints goes into CORP_STATE); then `scripts/census`
  (strict) on that copy (a marker the signer did not see, in a footer or a text box, is now in the signed copy); the md5
  manifest diff (`share-check.sh --diff <folder>`: after the adoption every file reads UNCHANGED — another CHANGED or
  GONE file means something besides the signature moved); and share-check on the folder, exit 0. A version rebuilt on the
  signer's copy is a NEW file beside it, never over it.
- **§GATE before any outward act the owner GO'd** — a deploy into a shared folder, a portal write into the owner's own
  systems, a configuration change (`cascade-gate.md`): deterministic checks first, recomputed by `jev gate` itself (the
  share-check and census receipts, every file's md5 from disk against the row's, the act's fields against the E0 row
  the owner's GO adopted — E12), then `jev gate` — veto mode on a row the owner's reply named by number (Jev can only
  block), the full 0.9 / 0.1 gate on a row adopted in the owner's own words; a reply that names no row authorizes
  nothing (E5). It is a floor under the owner's GO, never a substitute for it. **A send to a payer or any third party — a portal upload, a fax, an e-mail,
  an e-filing — is never a GO'd act:** HUMAN-ONLY, the loop stages it (E6). Assembling the `SEND TO` folder in the work
  folder is internal staging: no GO, no `jev gate` — only the deterministic checks that apply.
- **Recipient-capability check:** can the intended reader open it, navigate it and act on it in the software they
  actually use? PDF bookmarks were invisible in the recipient's viewer and became a printed contents page —
  **verified-correct is not verified-usable**. Per-person checklists, instructions in their language, a packaging
  warning wherever the mistake is expensive.
- **The report the owner reads** leads with the outcome and what they must decide, in complete sentences — no arrow
  chains, no campaign tags or labels they have not seen; every file or flag gets its own plain clause and an absolute path.

## §OWNER — decisions, carve-outs, the queue
- **E0 batch:** collect gated decisions into one numbered batch, take ONE go, execute inline at dispatch — N interrupt
  points become 1. Every row that would run an act carries the act's fields — verb, target path, recipient, record id,
  and each file it writes or sends with its md5 — written before the owner's GO (`templates/OWNER_QUEUE.md`). The owner's "GO
  1,3,4" adopts those rows verbatim; the GO record (the owner's words + the rows they name) goes into DECISIONS the same turn. A reply
  that names no row number and no act runs nothing: ask "GO which rows?" (CEO decision E5). Each GO'd outward act
  passes §GATE against its adopted row; anything a rail forbids gets its RAIL NOTE at that moment (rail 7), and the
  gate's decision is part of that note.
- **DECISIONS section,** written the same turn the answer arrives and **carrying the date**: the decision, **the owner's
  own words**, what it changed, where it is implemented — undated, it is a memory, not a record. An inference made on
  the owner's behalf is recorded **as inferred**, with its basis. A frozen decision may not be re-litigated: automatic REJECT.
- **Jev never decides an owner item.** The ladder governs verify spend upstream of the queue only; an owner-gated
  decision is never `jev_agree`'d onto the queue or off it, and §GATE never grants a GO.
- **Owner queue** (`templates/OWNER_QUEUE.md`): only decisions a human can make — a secret, a name, a price, a
  signature, a merge — ordered by your judgment, security first, each with owner, deadline, consequence-if-unanswered and
  the fallback at T-minus, tied mechanically to the artifact's gated markers so the two cannot drift. Cascade `declined`
  items (a source gap, as `[OWNER VERIFY: …]`) and gate reviews land here too; a cascade double failure does not — it
  goes to the front of the claim audit, which decides it (`cascade-gate.md`). **Split it
  by the clock whenever one exists** — "before the call" vs "after it, regardless" — so the owner can act on the first list in
  the minutes they have. A refused order gets one reason and one unblocking question, never a lecture.
- **GO-only classes.** Repository and account **configuration** — branch protection, secrets, integrations, webhooks,
  sharing settings — is a **named GO-only class**: no standing authority, executed only on an explicit owner GO naming
  the act, passed through §GATE, and logged as a RAIL NOTE at that moment. A blanket "I approve all of it" authorizes the
  act the owner named, never the merge, the publish or the send: those stay HUMAN-ONLY whatever the phrasing — and a portal
  upload, fax, e-mail or e-filing to a payer or other third party is a send, even through `jev-browse` (E6).
- **Defaults in force until the owner ratifies them** — carry each as a one-line question in the report, and do not soften the
  rail meanwhile: draft PR yes / merge no / publish no / repo and account config on an explicit GO only · `CORP_STATE.md`
  in a durable work folder (for software `~/<project>-audits/<date>-<slug>/`, never the product repo), never a
  scratchpad · isolated output plus an explicit archive-first,
  lock-checked, gated deploy for shared surfaces. **All three: default pending owner ratification.**
